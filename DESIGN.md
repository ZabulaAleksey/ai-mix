# AI Mix Assistant — Design

## 1. Назначение

AI Mix Assistant — не полноценная DAW и не замена Adobe Audition.

Главный пользовательский сценарий:

`Добавить треки → Анализ → AI предлагает фрагменты и порядок → Понять «почему» → Посекундно проверить микс → Настроить переходы → Прослушать → Экспортировать`.

Главный принцип интерфейса: **максимум музыкальной логики при минимуме элементов**.

AI выполняет анализ и предлагает решение, но пользователь всегда видит, что именно выбрано, почему это выбрано и как изменить решение вручную.

## 2. Основной экран

Приложение строится почти целиком вокруг одного рабочего экрана из трёх зон:

1. **Треки** — библиотека текущего проекта.
2. **Предложение микса** — объяснение AI и посекундный timeline.
3. **Переход** — настройки выбранного стыка между фрагментами.

Не создавать отдельные dashboard, тарифные экраны, социальные разделы, marketplace или постоянно открытый AI-chat.

Пример компоновки:

```text
┌──────────────────────────────────────────────────────────────────────┐
│ AI MIX                       Transport / Project                     │
├─────────────────┬────────────────────────────────┬───────────────────┤
│ ТРЕКИ           │ ПРЕДЛОЖЕНИЕ МИКСА             │ ПЕРЕХОД           │
│                 │                                │                   │
│ список треков   │ Как выбрал AI                  │ Track A → Track B │
│ BPM / key       │                                │ fade              │
│ duration        │ посекундный timeline           │ overlap           │
│ status          │ waveform / fragments           │ stretch           │
│                 │                                │ pitch             │
│                 │                                │ EQ smoothing      │
│                 │                                │ preview           │
└─────────────────┴────────────────────────────────┴───────────────────┘
```

## 3. Левая панель — треки

Основное действие: **+ Добавить треки**.

Для каждого трека показывать только:
- название;
- исполнителя, если доступен;
- BPM;
- тональность;
- длительность;
- статус анализа.

Подробные DSP-метрики не должны постоянно занимать место в списке.

Статусы:
- анализируется;
- анализ завершён;
- низкая уверенность;
- ошибка анализа.

## 4. Центральная зона — предложение AI

После анализа система предлагает:
- порядок треков;
- выбранные фрагменты;
- source-time каждого фрагмента;
- mix-time каждого фрагмента;
- переходы;
- краткое объяснение выбора.

### Как выбрал AI

Компактный блок должен отвечать на вопрос «Почему микс собран именно так?».

Пример причин:
- BPM совместим;
- гармоническая совместимость;
- подходящее изменение энергии;
- уверенная граница музыкальной фразы;
- низкий риск одновременного вокала;
- приемлемая стоимость time-stretch/pitch обработки.

Для подробностей используется действие **Почему?**. Внутренние значения анализатора показываются только по запросу.

## 5. Посекундный план

Timeline должен явно различать координаты исходного трека и итогового микса.

Пример:

```text
MIX TIME       TRACK          SOURCE TIME
00:00–00:42    Night Drive    02:14–02:56
00:42–01:18    Echoes         01:32–02:08
01:18–01:58    Resonance      03:05–03:45
```

Это часть доменной модели, а не только формат текста в UI.

## 6. Timeline

Каждый выбранный AI фрагмент отображается отдельным блоком с:
- названием трека;
- waveform;
- source start/end;
- mix start/end;
- зоной перехода;
- текущей позицией воспроизведения.

Overlap соседних фрагментов должен быть виден непосредственно на timeline.

Пользователь может:
- менять порядок drag-and-drop;
- менять начало и конец фрагмента;
- удалить фрагмент;
- выбрать другой фрагмент трека;
- вернуть рекомендацию AI.

Ручное изменение одного элемента не должно уничтожать остальные пользовательские решения.

## 7. Закрепление решений

Фрагмент или переход можно **закрепить**.

Закреплённые элементы не изменяются при повторной оптимизации.

Поддержать:
- `Пересчитать микс` — пересчитать незакреплённые части;
- `Пересчитать отсюда` — сохранить уже принятые решения до выбранной точки и пересчитать продолжение.

Это основной механизм итеративной совместной работы человека и AI.

## 8. Правая панель — переход

При выборе стыка открывается контекстный редактор перехода.

Для MVP нужны редактируемые параметры:
- тип перехода: `Crossfade`, `Beat Match`, `Cut`;
- fade length;
- overlap;
- time stretch;
- pitch shift;
- EQ smoothing.

Показывать исходную AI-рекомендацию и ручное значение, если пользователь его изменил.

Пример:

```text
AI: 12.0 s
Вы: 16.0 s
```

Должно быть действие **Вернуть рекомендацию AI**.

## 9. Предупреждения перехода

Предупреждения информируют, но не блокируют ручной выбор.

Примеры:
- высокий vocal overlap;
- низкая уверенность определения key/BPM;
- слишком большой time-stretch;
- clipping risk;
- спектральный конфликт.

## 10. Preview

Для выбранного перехода доступно быстрое **Прослушать переход**.

Прослушивается небольшой диапазон до и после стыка, а не весь микс.

Полезно поддержать loop выбранного перехода и A/B сравнение AI-варианта с ручным вариантом, но A/B не является обязательным для первого GUI.

## 11. Целевая длительность

Опциональная компактная настройка:
- автоматически;
- несколько быстрых пресетов;
- произвольная длительность.

Оптимизатор подбирает количество и длительность фрагментов под заданную итоговую длину.

## 12. Энергетическая форма

Будущее небольшое расширение без отдельного сложного редактора:
- нарастание;
- ровно;
- волна;
- спад.

Параметр задаёт стратегию optimizer'у и не превращает приложение в редактор automation curves.

## 13. Transport

Минимальный transport:
- play/pause;
- текущая позиция / длительность;
- переход к предыдущему/следующему фрагменту;
- loop выбранного перехода;
- preview volume.

Полноценный DAW transport не нужен.

## 14. Экспорт

Основные варианты:
- WAV;
- FLAC;
- project/timeline JSON;
- workflow передачи в Adobe Audition, когда адаптер доступен.

Неразрушающее состояние проекта сохраняется отдельно от rendered audio.

## 15. Визуальный стиль

Профессиональный тёмный интерфейс, а не cyberpunk-лендинг и не музыкальная социальная сеть.

Базовые поверхности: почти чёрный и графитовый фон, различия панелей преимущественно за счёт яркости и границ.

Семантические акценты:
- **голубой** — DSP-анализ, waveform, совместимость, техническая информация;
- **фиолетовый** — AI-рекомендации и автоматические решения;
- **янтарный** — риск, предупреждение, низкая уверенность, clipping/vocal overlap.

Цвет используется как информация, а не как декор.

## 16. Информационная плотность

По умолчанию показывать только информацию, нужную для текущего решения.

Chroma, spectral centroid, beat confidence и другие внутренние признаки скрывать за `Почему?` / `Подробнее`.

## 17. Главное правило AI UX

Каждое значимое AI-решение должно отвечать на три вопроса:

1. **Что выбрано?**
2. **Почему это выбрано?**
3. **Могу ли я изменить это вручную?**

Если хотя бы один ответ отсутствует, рекомендация считается недостаточно прозрачной.

## 18. Что не входит в основной интерфейс

Для MVP не нужны:
- регистрация и тарифы;
- dashboard;
- marketplace;
- социальные функции;
- классический большой mixer;
- VST rack;
- multitrack recording;
- mastering suite;
- сложный node editor;
- собственный файловый менеджер;
- постоянно открытый AI-chat.

Если функция уже качественно решается Adobe Audition, добавлять её только когда она непосредственно нужна AI-конвейеру.

## 19. MVP GUI

Минимальная рабочая версия должна уметь:
1. добавить треки;
2. показать статус и базовые результаты анализа;
3. получить AI-последовательность;
4. показать выбранные фрагменты;
5. показать source-time и mix-time;
6. объяснить выбор через «Почему?»;
7. показать waveform timeline;
8. выбрать переход;
9. изменить параметры перехода;
10. прослушать переход;
11. изменить порядок/границы фрагментов;
12. закрепить ручное решение;
13. пересчитать незакреплённую часть;
14. прослушать микс;
15. экспортировать результат.

Главный продуктовый цикл:

**AI предлагает → человек понимает → человек корректирует → система рендерит.**
